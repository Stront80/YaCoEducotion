# VPS-мастерская

Русскоязычный локальный симулятор настройки только что арендованного VPS для новичков. Учебный образ — Ubuntu 24.04 LTS. 18 уроков и итоговая практика: первый доступ, обновления, отдельный администратор, ключи/SSH, UFW, службы, журналы, копии и восстановление.

**Всё происходит с виртуальными данными браузера.** Нет подключения к VPS, исполнения shell, загрузки пакетов, настоящих ключей и изменения настроек ОС. IP 203.0.113.10 и отпечаток — учебные. Не вводите настоящие пароли, private keys и токены.

## Запуск

Из корня рабочего пространства:

```bash
python3 -m http.server 8771 --bind 127.0.0.1 --directory приложение/vps-trainer
```

Откройте **http://127.0.0.1:8771/**. Остановка — Ctrl+C. Из самой папки vps-trainer опустите `--directory приложение/vps-trainer`. Установка зависимостей не нужна. Если порт занят, выберите другой; прогресс привязан к браузеру и адресу с портом. file:// не является поддерживаемым способом запуска. Сервер раздаёт только каталог проекта и слушает loopback.

## Как работать

1. Выберите урок. Каждый имеет независимую среду с уже подготовленным начальным состоянием; итог начинается с чистого VPS.
2. Прочитайте задачу и проверьте контекст над полем: локальный компьютер, SSH-сеанс или консоль провайдера.
3. Введите команды по одной. Символы приглашения `$`/`#` вводить не нужно. Enter выполняет, стрелки вверх/вниз листают историю. Tab выходит из поля. На телефоне области переключаются вкладками «Урок», «Терминал», «VPS»; стрелки/Home/End работают, когда фокус на вкладках.
4. Локальные ssh/ssh-keygen/ssh-copy-id/scp выполняйте в «Локальной вкладке». Открытые соединения сохраняются кнопками ssh-N. Новое соединение проверяет новые правила, старое в модели остаётся открытым.
5. «Панель провайдера» раскрывает/сворачивает паспорт, снимок и восстановление. Отпечаток нужно сверить до ответа yes. Консоль восстановления — отдельная кнопка, не SSH.
6. `nano` для двух поддерживаемых файлов открывает простой редактор сайта. Нажмите «Сохранить файл» или «Отмена». Сохранение SSH-конфига не применяет его: нужны проверка и reload.
7. «Проверить задание» показывает отдельные цели. Просмотр подсказки/решения ничего не исполняет и не завершает урок. Памятка только подставляет текст команды.

Сброс урока подтверждается и заменяет его модель/историю/черновики, но сохраняет отметку прохождения. Восстановление snapshot также подтверждается и закрывает SSH-сеансы; это отдельное действие, не сброс всего курса. При повторном создании снимка запрашивается подтверждение замены.

## Что изучаем

- Первый доступ: паспорт/снимок, host key и SSH, ОС/диск/память/адрес/hostname/UTC, обновления, пользователь admin+sudo, ключевой вход и sudo.
- Защита без потери входа: права .ssh, копия SSH-конфига, проверка/применение и свежий вход, UFW, проверка службы/сокета, восстановление через консоль.
- Обслуживание: автообновления, nginx и нужный порт, журналы/диагностика, tar/scp/пробная распаковка, плановый reboot, возврат к snapshot.
- Итог: весь базовый путь до проверенной и вынесенной копии. Reboot и веб-сервер не входят в обязательные цели итогового задания.

## Модель и поддерживаемые команды

`help` содержит полный набор форм и флагов; произвольный Bash здесь не работает. Движок — JS-разбор фиксированных операций без eval, Function, shell, fetch/WebSocket и файловых API ОС. Серверные установки/команды sudo в уроках только меняют объекты модели.

- Локально: `ssh user@203.0.113.10`, `ssh -o PreferredAuthentications=publickey user@203.0.113.10`, `ssh-keygen -t ed25519`, `ssh-copy-id user@203.0.113.10`, `scp admin@203.0.113.10:/home/admin/app.tgz ./app.tgz`, `ls`.
- Диагностика VPS: `whoami`, `id [user]`, `cat` фиксированного файла, `hostnamectl`, `hostnamectl set-hostname имя`, `timedatectl`, `timedatectl set-timezone UTC`, `df -h`, `free -h`, `ip -brief address`, `ss -lntp`, `exit`.
- Администрирование: `sudo команда`, `sudo -v`, `adduser имя`, `usermod -aG sudo имя`, `chmod 700 ~/.ssh`, `chmod 600 ~/.ssh/authorized_keys`. Для эксперимента с ошибкой прав поддерживается 777. Права sudo захватываются новым сеансом после изменения групп.
- Пакеты: `apt update`, `apt list --upgradable`, `apt upgrade [-y]`, `apt install [-y] nginx|unattended-upgrades`.
- SSH: `nano /etc/ssh/sshd_config.d/00-workshop.conf`, `cp` между этим файлом и `.bak`, `sshd -t`, `sshd -T`, `systemctl reload ssh`.
- UFW: `default deny|allow incoming|outgoing`, `allow|deny OpenSSH|22/tcp|80/tcp`, `delete allow|deny 22/tcp|80/tcp`, `enable` с ответом y/n, `disable`, `status [verbose|numbered]`. Порт без /tcp тоже принимается. Первое совпадающее правило определяет результат модели.
- Службы: `systemctl status|start|stop|enable [--now]|is-enabled nginx|ssh`, статус `apt-daily-upgrade.timer`, `journalctl -u nginx|ssh --no-pager`, `curl http://localhost` (или 127.0.0.1), `reboot`.
- Автообновления: редактор `/etc/apt/apt.conf.d/20auto-upgrades`, `unattended-upgrade --dry-run --debug`.
- Копия: `tar -czf /home/admin/app.tgz -C /srv app`, `tar -tzf /home/admin/app.tgz`, `mkdir -p /tmp/restore-check`, `tar -xzf /home/admin/app.tgz -C /tmp/restore-check`, `cat /tmp/restore-check/app/settings.conf`.

### Существенные упрощения

- Первоначальный root/password-доступ — заданное условие образа провайдера в сценарии, не стандарт любой Ubuntu. Реальные образы могут начинаться с ubuntu и ключа, с заблокированным root. Интерактивные пароли adduser/sudo/SSH и вопросы пути/passphrase ssh-keygen заменены подписанным учебным состоянием. Нет реальной криптографии, изменения/ротации host key и проверки passphrase.
- Учебный SSH имеет четыре yes/no-директивы, фиксированный порт 22 и один ранний drop-in. Первое значение директивы побеждает. Нет полного sshd_config, Include/Match, cloud-init, PAM, AllowUsers, блокировки аккаунтов и socket activation. `sshd -T` рассчитывает файл с диска; активная конфигурация показана отдельно. Неверный файл не применяется; reboot читает диск заново и при ошибке оставляет SSH неактивным. Неизменённые настройки подставляются из правил сценария, а не системного sshd.
- Для key-входа модель строго требует .ssh=700 и authorized_keys=600. Настоящий StrictModes учитывает владельца, права родителей и другие допустимые сочетания. В модели нет полного VFS/ACL/SELinux/AppArmor.
- UFW рассматривается как общая модель IPv4/IPv6 без адресов источника и conntrack. Cloud-firewall, маршруты, DNS, исходящие ответы и отдельные IPv6-правила не моделируются. Открытый маршрут не гарантирует аутентификацию, слушающий сокет не доказывает внешнюю доступность. Старые SSH-сеансы сохраняются при смене правил как учебное упрощение; реальное поведение зависит от изменения и состояния соединений.
- Пакеты, журналы, характеристики, HTTP и время синтетические, reboot мгновенный. Установка unattended-upgrades сама не меняет учебный файл расписания: урок требует отдельного редактирования. В настоящей Ubuntu пакет/настройки могут уже присутствовать и быть включены. Dry-run проверяет два параметра расписания модели, без полного расчёта Origins, таймеров, блокировок и фактических обновлений.
- Снимок — копия данных сервера модели, без согласования приложений/БД и состояния реальных дисков/памяти. Восстановление не удаляет вынесенные локальные копии. Консоль провайдера всегда даёт root внутри модели; на реальном VPS доступ и процедура зависят от провайдера и ОС.
- tar/scp хранят копии JS-объектов, не создают/скачивают файлы на компьютер. Архивы и пробное восстановление ограничены одним учебным settings.conf. Нет фоновых сервисов, потоков, реальных БД и публичного сайта/TLS. Для настоящей БД нужен подходящий согласованный backup.
- Нет составных shell-команд, pipe, редиректов, переменных, подстановок и скриптов. Ошибка команды откатывает её изменение целиком; реальная команда может частично изменить систему. Учебная проверка не защищена от намеренного обхода учеником.

Лимиты: 5 пользователей, 8 открытых SSH-сеансов, 2000 символов команды, 8000 символов файла/черновика, последние 60 записей терминала и команд, 200 событий проверки, один снимок провайдера на занятие. Проверки шагов зависят от недавних событий: очень длинные эксперименты могут потребовать сброса урока.

## Сохранение

Ключ `vps-workshop-v1` в localStorage: последний урок, отметки, независимые модели VPS, логи/история, строка команды и незавершённый текст редактора. Очистка браузера удаляет прогресс; смена порта/адреса/браузера даёт другое сохранение. Используйте одну активную вкладку: последняя запись может заменить предыдущую. Экспорта/синхронизации/аккаунта нет.

При отказе записи сайт продолжает работу в памяти и предупреждает. Повреждённая/несовместимая запись не перезаписывается. Для ручного восстановления сначала сохраните старое значение, затем удалите только этот ключ в инструментах браузера.

## Разработка и проверки

- `engine.js` — VPS, команды, контексты и проверка снимков; API: run, action, saveFile, snapshot, VPS.restore.
- `lessons.js` — 19 занятий, независимые среды, решения/альтернативы, цели.
- `app.js`, `index.html`, `style.css` — интерфейс и сохранение. Ввод/вывод отображается textContent; CSP запрещает внешние соединения. Оболочка адаптирована из локальной Ubuntu-мастерской, прежние проекты сохранены.

Из папки проекта:

```bash
node --check engine.js
node --check lessons.js
node --check app.js
node tests/engine.test.cjs
```

45 тестов, 76 учебных вариантов и 5000 детерминированных команд/действий с проверкой структурных инвариантов. `tests/browser-checks.js` — async-функция для уже доступного Playwright page, создаёт изолированные contexts, требует сервер на 8771. Зависимости тестирования в проект не устанавливались. JSON — `tests/browser-results.json`, подробности — [проверки.md](проверки.md).

Настоящие SSH/UFW/systemd/apt для проверки модели не запускались, подключения к VPS не выполнялись. Тесты подтверждают поведение учебного движка, не полную совместимость с Ubuntu. Проверен Chromium; Firefox/Safari, реальные телефоны/IME, скринридеры и эффективность обучения не проверены.
