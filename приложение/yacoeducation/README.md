# YaCoEducation

Общий локальный сайт семи учебных мастерских: HTML/CSS/JS, JavaScript, Python, Ubuntu, Vim, tmux и VPS. В реестре 133 занятия. Каталог с поиском, фильтрами, сводкой прогресса и недавним курсом; мастерские открываются внутри общей оболочки с брендом YaCoEducation и переключателем.

Новые курсы подключаются через **[workshops.json](workshops.json)**. Существующие trainer-проекты остаются в соседних папках; их код и дизайн не переписывались. Сервер только раздаёт разрешённые файлы и читает реестр. Никакие учебные команды/код на сервере не исполняются.

## Один запуск

Из корня рабочего пространства:

```bash
python3 приложение/yacoeducation/serve.py
```

Откройте **http://127.0.0.1:8772/**. Остановка — Ctrl+C. Из самой папки yacoeducation: `python3 serve.py`. Для другого порта: `python3 serve.py --port 8780`.

Нужен Python 3.10+ и современный браузер с JavaScript; Python-мастерская также использует WebAssembly и модульный Worker. Внешние зависимости не устанавливаются, Pyodide уже хранится в соседней python-trainer. Один процесс обслуживает каталог и все семь курсов на 127.0.0.1. Не запускайте здесь обычный `python -m http.server`: ему неизвестны маршруты реестра.

Сохраняйте соседнюю структуру:

```text
приложение/
  yacoeducation/       # каталог, реестр, serve.py
  web-trainer/
  js-trainer/
  python-trainer/     # вместе с vendor/
  ubuntu-trainer/
  vim-trainer/
  tmux-trainer/
  vps-trainer/
```

Для переноса на другой компьютер нужны YaCoEducation и подключённые папки курсов по путям source. Сам каталог не копирует их содержимое в себя. Публичное размещение не выполнялось; сервер предназначен только для локального использования.

## Как учиться

- Найдите тему через поиск или направление, при необходимости отфильтруйте курсы по прогрессу.
- «Открыть мастерскую» сохраняет её как недавнюю и открывает общий экран практики. Обучение/проверка/подсказки остаются внутри выбранного курса.
- Над мастерской доступны «Все мастерские», переключатель курсов, прогресс и «Режим практики», уменьшающий внешнюю шапку. «Открыть отдельно» использует тот же адрес сохранения, но открывает курс без оболочки в новой вкладке. Не редактируйте один курс сразу в двух вкладках.
- Прокрутка содержимого мастерской находится внутри учебной области. На телефоне используйте также собственные вкладки курса. Внешняя страница может прокручиваться, когда панель навигации выше экрана.
- Все занятия доступны сразу. Примерные маршруты — подсказки выбора, не обязательные программы.

При переключении курса предыдущий iframe удаляется: запущенная программа/Worker завершается. Сохраняемые черновики/состояния остаются в localStorage; это не перенос памяти работающей программы.

## Прогресс и прежние порты

**Общий адрес 127.0.0.1:8772 — отдельное хранилище браузера.** Старые сохранения на 8765–8771 остаются на прежних адресах. Автоматического переноса между портами/origin и облачной синхронизации нет. Для старого прогресса запустите соответствующую мастерскую на прежнем порту и в том же браузере. localhost и 127.0.0.1 также считаются разными origin.

Каждый курс использует собственный прежний ключ (`web-workshop-v1`, `js-workshop-v1` и т. д.). Каталог **только читает** их completed и считает уникальные известные lessonIds из реестра. Незнакомые/повторные ID не увеличивают счётчик. Это сводка отметок, а не дополнительная проверка знаний или полного содержимого снимка курса.

Каталог хранит только `{version:1,last:id}` в ключе `yacoeducation-v1`. Обновления из iframe приходят через storage-событие, без пересоздания учебного документа. Повреждённый/недоступный прогресс показывается отдельным статусом; такие записи каталог не перезаписывает. При отказе хранилища можно продолжать в памяти. Если повреждена запись самого каталога, новая last-запись также не сохраняется поверх неё.

Очистка данных браузера/смена адреса теряют доступ к сохранению. Используйте один активный сеанс курса. Экспорта/импорта, аккаунтов и восстановления облачных копий в первой версии нет.

## Добавить новую мастерскую

1. Поместите готовый статический сайт в новую папку внутри `приложение/`, например `git-trainer/`. В ней должен быть `index.html` с title и локальными ресурсами. Для сборного проекта source может указывать на его dist. Сервисы backend и команды установки автоматически не запускаются.
2. Добавьте объект в массив workshops файла `workshops.json`. Пример для мастерской без общего счётчика:

```json
{
  "id": "git",
  "title": "Git",
  "subtitle": "Первый репозиторий и понятная история",
  "category": "Инструменты",
  "badge": "Git",
  "accent": "blue",
  "mode": "Учебный симулятор",
  "description": "Описание возможностей вашей готовой мастерской.",
  "topics": ["Коммиты", "Ветки"],
  "level": "С нуля",
  "lessonCount": 10,
  "source": "../git-trainer",
  "progress": null
}
```

Это **пример**, готовой Git-мастерской в комплекте нет. Категории выводятся из реестра автоматически. Можно добавить новую категорию текстом. Варианты accent: blue, amber, violet, coral, green, teal, slate. Badge — до 5 символов. ID — уникальный латинский slug; смена ID меняет URL, а смена storageKey — источник сводки прогресса.

Если мастерская сохраняет отметки в совместимом формате, замените progress:

```json
{
  "storageKey": "git-workshop-v1",
  "version": 1,
  "lessonIds": ["git-1", "git-2"]
}
```

Число уникальных lessonIds должно точно совпадать с lessonCount (в этом коротком примере lessonCount должен быть 2). Сама мастерская должна записывать `{version:1,completed:["git-1"]}` в этот ключ; остальные её поля могут быть собственными. При другом формате используйте progress:null либо отдельно реализуйте адаптер. Без адаптера курс доступен, но показывает «Без общего счётчика» и не попадает в фильтры начатых/пройденных.

3. Проверьте реестр, не запуская сервер:

```bash
python3 приложение/yacoeducation/serve.py --check
```

4. Если проверка прошла, обновите каталог в браузере. Сервер читает реестр при запросах, перезапуск не нужен. Открытая ранее вкладка каталога сама не отслеживает файловые изменения; нужна перезагрузка. Не меняйте реестр посреди выполнения задания.
5. При желании добавьте ID в paths — необязательные маршруты выбора. Неизвестные или повторные ID не принимаются.
6. Откройте новый курс внутри оболочки и проверьте код/Worker/ресурсы/сохранение/узкий экран. Добавление записи не доказывает совместимость произвольного сайта.

Перед редактированием сделайте копию workshops.json. Ошибочная запись отклоняет реестр целиком: `--check` сообщает проблему, запрос API возвращает 503, сайт показывает ошибку и кнопку повтора. На старте сервер с неверным реестром не запускается. Нет кнопок записи реестра через сайт.

### Контракт подключения

- До 60 курсов, 1–1000 занятий в каждом; все обязательные поля и пределы проверяет load_registry в serve.py.
- source — относительный путь от workshops.json к папке внутри `приложение/`; абсолютные пути и выход за эту папку запрещены. Symlink ресурсов проверяется после раскрытия.
- URL назначается автоматически: `/workshops/ID/`, маршрут оболочки — `/#/workshop/ID`.
- Пути ресурсов внутри мастерской должны быть относительными к её папке. Абсолютные ссылки `/app.js` принадлежат каталогу, а не курсу. Разрешите в CSP встраивание в тот же origin; чужие X-Frame-Options/CSP могут помешать работе.
- Допускаются браузерные HTML/CSS/JS/MJS, изображения SVG/PNG/WebP/JPG/JPEG/ICO, WASM/DATA/ZIP/JSON и корневой harness.py для Python-мастерской. Другие типы ресурсов требуют явного расширения разрешённого списка в сервере.
- Тесты, screenshots, node_modules, __pycache__, скрытые файлы, README/Markdown и серверные .py по учебным маршрутам не раздаются. Listing каталогов отсутствует.
- Учебные сайты доверенные и работают в одном origin. Общая оболочка не добавляет sandbox поверх действующих курсов, чтобы не ломать Workers/WASM/сохранение. Sandbox веб-мастерской и собственные CSP курсов сохранены. Это не изоляция недоверенных сторонних сайтов: общий origin делит хранилища и доступ к DOM. Не подключайте чужой вредоносный код и не храните секреты в этом origin.
- Настройки Linux/SSH/firewall/DNS не меняются. HTTP GET/HEAD читают ресурсы; POST/PUT/PATCH/DELETE возвращают 405. Открытого порта во внешней сети и авторизации нет.

## Проверки и устройство

```bash
python3 приложение/yacoeducation/serve.py --check
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s приложение/yacoeducation/tests -p 'test_*.py' -v
node приложение/yacoeducation/tests/core.test.cjs
node --check приложение/yacoeducation/app.js
node --check приложение/yacoeducation/core.js
```

- `serve.py` — проверка реестра, API и раздача по разрешённым путям.
- `workshops.json` — единственный реестр курсов/источников/адаптеров и маршрутов.
- `core.js` — проверка публичных данных, поиск, прогресс и маршруты.
- `app.js`, `index.html`, `style.css`, `icon.svg` — каталог и общая оболочка.
- `tests/` — 11 Python-тестов и 11 Node-тестов, browser-checks.js и фактический JSON.

Браузерный сценарий — async-функция для существующего Playwright page; использует изолированные contexts и сервер на 8772. Пакеты для тестирования не устанавливались. Проверены все семь мастерских с выполнением одного задания, включая Python/WASM и веб-sandbox, сводка/переходы/сохранение/ошибки, пять ширин и текст 200%. Это интеграционная проверка, не повторное прохождение всех 133 занятий. [Подробный отчёт](проверки.md).

Источники по устройству: [storage-событие браузера](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event), [Python http.server](https://docs.python.org/3/library/http.server.html). Сервер предназначен для локальной разработки, без заявления готовности к production. Другие браузеры, реальные мобильные устройства/IME и скринридеры не проверялись. Сайт не публиковался.
